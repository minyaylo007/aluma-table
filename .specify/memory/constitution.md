# Constitution — ALUMA (table.central-aparts.store)

При конфликте действуют ~/maestro/OWNER-RULES.md и CLAUDE.md проекта. Этот файл их не
копирует — ссылается и фиксирует то, что проверяют /speckit-plan, /speckit-analyze и /speckit-converge.

## Источники правил (прочитать до работы)
- ~/maestro/OWNER-RULES.md — правила владельца, выше всего остального.
- ~/.claude/CLAUDE.md — правила машины ace-main: чужие бизнесы, Caddy, порты, процессы.
- CLAUDE.md в корне репозитория — правила и контекст проекта.
- ~/maestro/PORTS.md — реестр портов; новый порт сначала вписывается туда.

## Инварианты (MUST; нарушение — CRITICAL в analyze)

### I. Тесты до пуша
Каждое изменение поведения идёт с тестом. Перед пушем MUST быть зелёными: python -m unittest discover -s tests -t . в venv вне дерева (CLAUDE.md §8); при правке site/ — Playwright по CLAUDE.md §6.
Где есть сборка — python3 build.py (exit 0; обязателен при правке site/, i18n/, content.json, build.py) перед пушем. Красные тесты не пушатся и не «чинятся» пропуском.

### II. Секреты и персональные данные — никогда
Ключи, пароли, токены, персональные и медицинские данные MUST NOT попадать в код, логи, коммиты,
спеки, тесты и отчёты. Секреты — только в .env вне git; в репозитории — .env.example.
В спеках, фикстурах и примерах — только синтетика.

### III. Никаких новых зависимостей от AWS
Новый код MUST NOT добавлять зависимостей от AWS (SDK, S3, SES, SQS, Lambda, Cognito, RDS и т. п.).
Замена — сервисы на своей машине. Облачных баз (Supabase cloud, Firebase, Neon…) не заводим.

### IV. Сеть: только 127.0.0.1 и свой порт
Процесс слушает MUST только 127.0.0.1 и только порт проекта из PORTS.md: 8005 (API, gunicorn всегда с --no-control-socket) и 8007 (локальный просмотр для тестов).
Caddy не запускается, не останавливается и не перезагружается; порт 2019 не трогается ничем.

### V. Чужое не трогать
/opt/{iiko,uzd,uzd-legacy,atmo,tennis,bots}, /etc/caddy, чужие юниты, контейнеры и порты —
только чтение, где разрешено. Процессы гасятся только по PID, никогда по имени.

### VI. Git
Коммит после каждого законченного шага, git add — явным списком путей, push сразу,
push --force — никогда. Основная ветка: master. Выкат — по docs/DELIVERY.md проекта. Автодеплой после попадания в целевую ветку разрешён и желателен
(OWNER-RULES п.22), если проверки CI зелёные и откат проверен; выкат в прод вне этого конвейера —
по-прежнему только с «да» владельца. Переключение DNS — по docs/CUTOVER-CHECKLIST.md.

### VII. Простота и границы
Делается то, что в spec.md, и не больше. Новая зависимость, сервис или порт — только с
обоснованием в plan.md (Complexity Tracking) и согласием дирижёра.

## Как устроен SDD в проекте
- SDD — фича больше ~1 дня или затрагивает данные, деньги, вход, безопасность.
  Мелкие правки и эксплуатация — обычным заданием, без specs/.
- Фичи — specs/NNN-short-name/; номер назначает дирижёр, short-name латиницей.
- Спецификатор коммитит только specs/NNN-x/; исполнитель — коммит после каждой фазы tasks.md.

## Специфика проекта
- Что это: лендинг одного раздвижного дубового стола (иврит RTL на /, английский на /en/), форма заявки → Telegram владельцу → /admin (CLAUDE.md, шапка).
- Стек: build.py → dist/, api/handler.py один и тот же в Lambda и под gunicorn, хранилище по FX_STORAGE — DynamoDB или SQLite (CLAUDE.md §2, §3).
- Критичные потоки — не менять без отдельной спеки: заявка POST /api/fx/lead и уведомление, вход в /admin и его cookie, хранилище и перенос данных (scripts/migrate_fx.py), EDGE_SECRET (CLAUDE.md §3, §9).
- Прод и выкат: сейчас AWS-стек fx-table, идёт переезд на эту машину (CLAUDE.md, шапка; §9 «Deploy is owner-only»).
- Особое: факты — только в content.json и i18n/*.json (§1); сборка побайтно одинакова на любой ОС (§1); dump/ и data/ — живые заявки, не печатать и не коммитить (§9).
