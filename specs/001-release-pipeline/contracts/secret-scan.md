# Contract: скан секретов [флот; шаблоны данных — ALUMA]

## `scripts/secret_scan.py`

```
python3 scripts/secret_scan.py --repo <корень репозитория или голое зеркало> \
    [--mode tree|history|blobs|all] [--rev <ревизия> ...] [--logs <папка журналов Actions>] \
    [--baseline <файл.json> [--update-baseline]] --report <файл.md>
```

Только стандартная библиотека. Ни gitleaks, ни trufflehog, ни любых новых двоичных из сети
(правило флота 13.09.2026) — иначе обязательная проверка зависела бы от загрузки со стороны.

**Источники (`--mode`, по умолчанию `all`):**

| режим | что читает | что ловит |
|---|---|---|
| `tree` | `git ls-files` рабочего дерева | то, что вносят сейчас; режим обязательной проверки CI |
| `history` | добавленные строки диффов `git log <--rev> -p` | то, что удалили из дерева, но не из истории |
| `blobs` | `git rev-list --objects <--rev>` + `cat-file` | содержимое, не попавшее в дифф: слияния, оборванные ветки |
| `all` | всё перечисленное | разовый разбор истории |

**Объём истории — `--rev`** (можно несколько раз, по умолчанию `--all`). Так публичная история
отделяется от приватного архива. Значение, начинающееся с `-`, передаётся через `=`:

```
--rev refs/remotes/origin/master                            # только то, что видит мир
--rev=--all --rev=--not --rev refs/remotes/origin/master    # только приватный архив
```

**Что выводится:**

- В **stdout** — ТОЛЬКО итог по правилам (`<правило>: <сколько>`) и общее число. Ни пути, ни
  коммита, ни значения: журнал прогона публичного репозитория читает весь мир.
- В **отчёт** (`--report`, пишется под `umask 077`) — правило, путь, число совпадений, длины
  совпадений, необратимый отпечаток `sha256[:12]` и места (`<короткий sha>:<строка>`). Отпечаток
  считается только для классов с высокой энтропией (ключи, токены); для персональных данных —
  никогда: пространство значений мало и хеш подбирается перебором.
- **Значение — ключ, телефон, имя, код двери — не попадает никуда.** Правило владельца 10.

**Базовая линия (`--baseline`)** — список уже просмотренных мест вида «правило, путь, сколько
совпадений», без значений и без номеров строк (строки сдвигаются от любой правки). Находка из
списка помечается известной и код выхода не поднимает; код выхода 1 дают только НОВЫЕ.
`--update-baseline` перезаписывает файл текущими находками — только после осознанного просмотра.
Файл проекта: `.github/secret-scan-baseline.json`; худшие классы (ключи, приватные ключи, файлы
`.env`, базы, коды доступа) в него не попадают никогда — закреплено
`tests/test_secret_scan.py::RepositoryBaselineTests`.

**Код выхода:** 0 — новых находок нет; 1 — есть; 2 — ошибка запуска (нет папки, не корень
репозитория, нечитаемая базовая линия, `--update-baseline` без `--baseline`).

**Правила** — `CONTENT_RULES` (по содержимому строки) и `_path_rule` (по пути: файл, которого в git
быть не должно, независимо от содержимого). Набор общий на весь флот и сверен с бек-офисом
13.09.2026; у каждого правила есть красный и зелёный случай в `tests/test_secret_scan.py`.

## Обязательная проверка `secret-scan` в конвейере

`.github/workflows/ci.yml`, задание `secret-scan` — первая из шести обязательных проверок ruleset
`master` (`.github/rulesets/master.json`; состав — `docs/DELIVERY.md` §3).

- `--mode tree --baseline .github/secret-scan-baseline.json --report "$RUNNER_TEMP/secret-scan.md"`.
- **Без условий (`if:`) и без фильтров путей (`paths` / `paths-ignore`)** — правило флота 13.09:
  скан выполняется ВСЕГДА, его не выключают даже на коммите в один `.md`. Именно такой скан нашёл
  в другом проекте коды от дверей и пароль WiFi — и нашёл их в документах, а не в коде.
- На `master` те же проверки запускает `release.yml` заданием `checks` (`workflow_call` того же
  `ci.yml`), поэтому новое задание попадает и в этот путь автоматически.
- Отчёт остаётся в `$RUNNER_TEMP` прогона и никуда не публикуется (ни артефактом, ни в журнал).
- Стоит секунды и не тратит оплаченных минут: репозиторий публичный.

Закреплено `tests/test_workflows.py` (состав заданий, отсутствие условия и фильтров путей,
отсутствие сторонних сканеров) и `tests/test_rulesets.py` (контексты обязательных проверок
сверяются с именами заданий `ci.yml`).

## Разовый разбор всей истории (фаза 1 и повтор 13.09.2026)

1. Временная папка вне дерева: `umask 077`, `mktemp -d /tmp/aluma-scan-XXXXXX`.
2. `git clone --mirror` обоих репозиториев — публичного `aluma-table` и приватного архива
   `aluma-table-archive-2026-09`.
3. `scripts/secret_scan.py --mode all` по каждому зеркалу отдельно: публичная история — срочно,
   приватный архив — нет (его историю не переписывают, Actions выключены).
4. Журналы Actions: `gh run list --limit 1000 --json databaseId` → `gh run view <id> --log >
   <tmp>/logs/<id>.log` → тот же скан с `--logs`.
5. Решающая сверка: отпечатки боевых значений из `~/.config/aluma/aluma.env` сравниваются с
   отпечатками строк-кандидатов истории. Совпадение = значение действительно утекло.
6. Отчёт числами, без значений: `docs/security/secret-scan-2026-09-13.md`; временная папка
   удаляется. Отчёт фазы 1 — `specs/001-release-pipeline/secret-scan-report.md`.

Фаза 1 планировала здесь ещё и gitleaks закреплённой версии; с 13.09.2026 это отменено —
сторонних сканеров и новых двоичных из сети не ставим.

## Решение

- Находок нет → объявление дирижёру → следующий шаг (смена видимости в фазе 1; слияние PR сейчас).
- Есть настоящая находка в ПУБЛИЧНОЙ истории → **ничего не коммитить**, стоп, дирижёру одной
  строкой: тип, файл, коммит. Решение о ротации принимает владелец.
- Заведомые находки без значений (AWS account id и ARN в `infra/samconfig.toml.example`,
  синтетические телефоны фикстур, регулярные выражения разбора телефона) → просмотр поимённо и
  базовая линия, а не отключение правила.
