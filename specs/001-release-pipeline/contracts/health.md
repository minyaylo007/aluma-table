# Contract: `GET /api/fx/health` [ALUMA; поля — флот]

Эндпоинт не трогает хранилище (как и сейчас). Меняется только тело ответа: добавлено `git_sha`.

**Ответ 200** (`Content-Type: application/json`, `Cache-Control: no-store` — как у всех ответов `resp()`):

```json
{"ok": true, "version": "v0.5.0", "git_sha": "0123456789abcdef0123456789abcdef01234567", "ts": "2026-09-12T10:00:00Z"}
```

| Поле | Источник | Правило |
|---|---|---|
| `ok` | — | всегда `true` |
| `version` | env `APP_VERSION` (по умолчанию `0.0.0`) | на машине после деплоя — ровно имя тега `vX.Y.Z` из `RELEASE.env` |
| `git_sha` | env `GIT_SHA` | 40 hex из `RELEASE.env`; если переменной нет или она пустая — `null` (Lambda, локальный запуск) |
| `ts` | часы сервера | ISO 8601 UTC, как сейчас |

Одинаково в Lambda и под gunicorn. Никаких других полей, секретов, путей.

**Кто читает.** Агент — `http://127.0.0.1:8005/api/fx/health` (локальная проверка); задание `deploy` — адрес из
переменной `ALUMA_HEALTH_URL` (публичная проверка). Успех = `ok` И `version` = тег И `git_sha` = полный sha тега.

**Совместимость.** Существующие потребители (`scripts/smoke_local.py`, чек-листы) читают `ok` и `version` —
добавление поля их не ломает.
